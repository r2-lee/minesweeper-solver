# Hill Java 按需加深猜测的同盘 A/B

原版赢 5,475 / 10,000 局，新版赢 5,483 / 10,000 局。配对胜率差为 **+0.08 个百分点**，95% 配对 bootstrap 区间为 **−0.02 至 +0.19 个百分点**。新版单独赢 18 局，原版单独赢 10 局。

| --- | ---: | ---: | ---: |

489 个猜测局面进入筛选，198 次达到 0.5 个百分点门槛，128 次完成最优选点的证明。实际改点 120 次，覆盖 114 张盘。其余 9,886 张盘的猜测轨迹和胜负均与原版逐盘一致。

## 新档位

LARGE_ADAPTIVE_ANALYSIS 沿用原版 LARGE_ANALYSIS 的预算。全盘深搜因预算跳过或未完成、且原版回退成单格猜测时，尝试枚举至多 40,000 张一致雷图。对原选点和候选使用同一个固定的便宜续局策略估分，每张雷图等权。最佳候选估分高至少 0.5 个百分点时，启用最多 130 万节点的加深分析。能证明候选比原选点更优时才改点。可通过 SettingsFactory.GetSettings(Setting.LARGE_ADAPTIVE_ANALYSIS) 启用。

## 样本与复跑

Hill 基线为 827e5b9b898ec9b8a8b03383b42a374ad12586b1。用种子 20261118 和 20261119 各生成 5,000 张 16×30、99 雷专家盘，固定首点 (3,3)（零基）并保护其九宫格。本批无重复，也与此前的 1 万张盘无重复。配对区间用同盘胜负差重采样 100,000 次。

两组使用同一 JDK 21.0.9、8 个跑盘线程、每个求解器内部单线程和 NO_FLAG。每组先跑 192 局预热，计时随后开始。两个 1 万盘批次顺序运行。两个种子的胜率差分别是 +0.04 和 +0.12 个百分点。

门槛边界、预算回退和后续搜索通过了小局面检验。Java 枚举逐张匹配之前 199 个精确局面的雷图，实盘接口也完成了历史 128 盘的试跑。

[补丁](hill-adaptive.patch) 可应用到固定的 Hill 提交。[复跑资料](ab-evidence.zip) 包含逐局结果、新雷图、生成与汇总脚本，以及跑盘设置。解压后，在 PowerShell 7 指定原版和应用补丁后的工作目录。汇总脚本需要 Python 3.12 或以上。

~~~powershell
.\run-ab.ps1 -Stock 'C:\repo\hill-stock' -Adaptive 'C:\repo\hill-adaptive' -Jdk 'C:\jdk-21' -Output 'C:\runs\adaptive-replay'
~~~
