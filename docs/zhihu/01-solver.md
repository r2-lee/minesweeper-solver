# 扫雷算法的思想：确定性、概率、和"赌哪一格"

> 这篇不介绍某一个实现，而是回答：**今天写一个扫雷求解器，思想上有哪几块、哪些已经有共识的答案、分歧在哪里。**
>
> 两个参照：David Hill 的 JSMinesweeper（公开实现里胜率最高、分层最干净）和 EdLogg 的 C++ 实现（风格完全不同，胜率几乎一样）。
> 文中所有"我们"的实测，基准都是 §3 那条策略——**精确边际概率 + 选最安全格**，**不是**在 Hill 的代码上改。

---

## 〇、背景：两个可比的数字，和一条二十年的曲线

### 0.1 两个可比的数字

同一批棋盘、同一首点（(3,3)、九宫格无雷）、同样 16×30/99，各跑几十万局：

| 求解器 | 语言 | 高级胜率 | 猜测/局 |
|---|---|---|---|
| **Hill（`LARGE_ADAPTIVE_ANALYSIS`）** | Java | **54.59%**（10 万 + 5 万复核，合并 15 万） | 2.65 |
| **EdLogg** | C++（MFC） | **53.97%**（50 万局） | 2.28 |

（Hill 的数字是 10 万局 + 新种子 5 万局复核的合并；EdLogg 是把他的 `tank.cpp`/`fastSolve.cpp` 原样编成命令行程序，用同一个发牌器喂 50 万张盘跑出来的。）

两个结论：

1. **高手之间的差距只有 0.6 个百分点**（Hill 54.59 vs EdLogg 53.97，z≈3.5）。上到 54% 以后，比的不是"有没有绝招"，而是每一层有没有做干净。
2. **怎么猜很有策略讲究**：如果正常做，胜率大概是 50%，而 Hill 能突破这个极限——这正是本文要讲的东西。

### 0.2 简史：2019 年之前，最好也就是 40% 出头

把公开能查到的数字按年份排一下，会让你对这 54% 有完全不同的理解：

| 年份 | 谁 / 哪个实现 | 方法 | 高级胜率 | 口径 |
|---|---|---|---|---|
| 1995 | Ramsdell 的 **PGMS** | 单点规则 + 方程 | 无公布数字（后来都拿它当基准） | classic |
| 2001 | **Studholme**（多伦多） | CSP 约束满足 | **33.9%**（当时世界纪录），初级 80.0% | classic |
| 2004 | **Pedersen** | limited search + 概率估计 | **30.0%**，中级 77.8%（世界纪录） | classic |
| 2012 | **大森瑛智 / 井上真郷**（IPSJ SIG-GI） | 二体探索 + 全模式枚举 + 并列处理 | **49.4%** | 摘要未写首点规则 |
| 2012 | **Couëtoux 等**（INRIA RR-8041） | MCTS + 信念状态估计 | **34% / 38.1% / 38.7%**（CSP-PGMS / HCSP / OH） | 每步 100 次模拟 |
| 2017 | **Tu 等**（AAAI-17 workshop） | 概率 + 策略组合 | **39.60%**（PSE）；单策略 39.14 / 35.56 / 35.05 | 30×16/99 |
| 2018 | **EdLogg** 公开版 | 周长建模 + 端局暴力 | **46.92% ±0.11** → 他后来更新到 53.96% | 首点 (3,3) |
| 2019 | **Hill**（JSMinesweeper） | 五层 | **54.3%** modern / **41%** classic | — |

出处（按图索骥）：Studholme 2001 见 [minesweepergame 论文目录](https://web.archive.org/web/20220322011936/https://minesweepergame.com/math-papers.php)（[PDF](https://minesweeper.info/articles/MinesweeperConstraintSatisfaction.pdf)）；Pedersen 2004 见[论文 PDF](https://minesweepergame.com/math/the-complexity-of-minesweeper-and-strategies-for-game-playing-2004.pdf)；大森/井上 2012 见 [CiNii](https://cir.nii.ac.jp/crid/1571135652847110912)；Couëtoux 见 [INRIA RR-8041](https://inria.hal.science/hal-00723550v1/preview/RR-8041.pdf)；Tu 等 2017 见[论文 PDF](https://minesweepergame.com/math/exploring-efficient-strategies-for-minesweeper-2017.pdf)；EdLogg 的 46.92% 出自他在 [puzzling.SE 的公开帖](https://puzzling.stackexchange.com/revisions/caefef6f-71fb-40f3-a415-219c1f60878b/view-source)；Hill 的两档数字原话在 [JSMinesweeper README](https://github.com/DavidNHill/JSMinesweeper)。

**1995–2004：先把"能算的算完"，30% 出头。** Ramsdell 的 PGMS（1995）第一次把"单点规则 + 方程"写进程序；Studholme（2001）把它换成 CSP，高级从个位数拉到 **33.9%**，是当时的世界纪录。Pedersen（2004）加"小范围搜索 + 概率估计"到 **30.0%**，但同一篇论文里"只用单点规则"的版本在专家难度只有 **0.5%**——这条数字很能说明问题：**光把确定性做干净，就已经是 30 个点的差距。**

**2012–2017：概率算得更准，但仍在 34–40%。** Couëtoux 等用 MCTS + 信念状态估计，专家盘 34% → 38.7%（每步 100 次模拟）；Tu 等在 AAAI-17 做了一次系统化比较，最好的组合（概率 + 策略）也只有 **39.60%**，单策略里"纯概率" 35.56%、"最小风险" 35.05%。大森/井上（2012）报的 **49.4%** 是能查到的最高的"前 Hill"数字，但摘要里没写清首点规则和盘面生成方式，引用时得打个问号。

**2018–2019：两年涨 14 点。** EdLogg 2018 年公开的版本是 **46.92%**（首点 (3,3)，bootstrap 误差 ±0.11），后来他自己更新到 53.96%；Hill 的 JSMinesweeper（2019）直接给到 **54.3%**。这两位的做法和前面那批人不一样：概率照算，但把力气花在**并列候选怎么排**和**端局要不要深搜**上——这两个维度在 2017 年那篇 AAAI 论文里根本没被当成一个方向。

**别被数字骗了：有一半是规则涨的。** Hill 自己写得很清楚：他的求解器在 classic expert（首点只保证不炸、通常点角）是 **41%**，在 modern expert（首点 (3,3) 且九宫格无雷）是 **54.3%**——**同一个程序，规则一换差 13 点**。我们实测"第一下能不能开出一片空区"这一个变量值 **+17 点**。所以 2001 年那个 33.9% 换算到 modern 口径大概还要加十几个点，也就是说**当年那条 CSP 路线可能已经摸到 45% 附近**；后面那 10 点，才是 Hill 和 EdLogg 真正加出来的。

本文接下来就拆这两件事：这 10 点是被什么加出来的，以及我们自己试了十几种改法、到底加出来了多少。

## 一、把问题拆开：三层，只有最后一层是"设计"

一个求解器每一手只输出一个动作，但支撑这个动作的是三层东西：

| 层 | 它回答的问题 | 输出 | 有没有设计空间 |
|---|---|---|---|
| **1. 确定性** | 当前局面里，哪些格子已经被推死了？ | "确定是雷"/"确定安全"的格子集合 | **没有**（集合是局面的属性） |
| **2. 概率** | 剩下的未知格，各自有多危险？ | 每格是雷的概率 | 几乎没有（同一套计数直接给出） |
| **3. 选择** | 没有免费动作时，该赌哪一格？ | 一个动作 | **全在这里** |

### 1.1 第 1、2 层其实是同一次计算

数出"所有与当前信息自洽的雷图"之后：

- 某格在**所有**图里都是雷 / 都不是雷 → 它属于确定集（第 1 层）；
- 其余格子，"它是雷的图数 ÷ 总图数"就是它的雷概率（第 2 层）。

所以这两层不是两套算法，而是**同一次计数的两个输出**。它们的作用是：把"根本不需要赌"的部分吃干净，同时保证你不会把赌注押在已经推死的格子上（那是 bug）。

落到操作上，接口非常简单：

- 表里存在概率 **0** 的格子 → 开它（免费推进，而且常常带出一整片连锁）；
- 存在概率 **1** 的格子 → 标它（减少"剩余雷数"，让后面的计数更紧）；
- 两者都没有 → 进入第 3 层，开始赌。

**"确定性做完了"的定义就是：局面里再也找不到 0 或 1 的格子。** 这句话同时也是第 3 层的入口条件。

### 1.2 为什么"一局要赌几次"是第 3 层决定的

第 1 层只回答"**此刻**哪些格子是逻辑必然的"。如果它做全了，那么此刻剩下的不确定性是"信息不足"，而不是"推理不足"——再怎么推理也变不出新的确定格。**能让局面重新变得可推的，只有"翻开一格"这个动作**，而翻开哪一格是第 3 层决定的。所以：

- 第 1、2 层的产出是"**哪些格子不必赌**"；
- 第 3 层的产出是"**后面还有多少次赌、每次多危险**"——不同的选点会翻开不同的数字，牵出长度不同的确定性链条。

一个直接的反例：EdLogg 和 Hill 的确定集是同一个（都是当前局面下能推死的格子），但 EdLogg 平均 **2.28 次/局**，反而少于 Hill 的 **2.65 次**——因为他的猜法更愿意"早点去空区换推进"。**这说明赌几次不是"确定性做得好不好"的函数，而是"猜法怎么选"的函数。**

### 1.3 一个能用的胜率模型

```
胜率 ≈ q^n
```

- `n` = 每局平均被迫猜测的次数（第 3 层的产出）；
- `q` = 每次猜测的平均存活率（第 3 层的另一个产出）。

用实测数据反推：Hill `n≈2.65`、`q≈0.796`；EdLogg `n≈2.28`、`q≈0.769`。乘积分别对上 54.6% 和 54.0%。

**这条公式说明优化只有两个方向——少赌一次，或者每次更安全一点——而这两个方向都在第 3 层，而且互相牵制**（想把 `n` 压小，往往要更早冒险，于是 `q` 变低）。

## 二、第一层：确定性——把当前能确定的格子全算出来

### 2.1 先定义清楚：什么叫"确定"

给定当前局面——已开的数字、已标的雷，以及"全盘还剩 `M` 颗雷"这个事实——考虑**所有与这些信息一致的雷图**。对某个未知格 `c`：

- 若它在**每一张**这样的雷图里都是雷 → `c` 是"确定是雷"；
- 若它在每一张里都不是雷 → `c` 是"确定安全"；
- 否则 `c` 不确定，只能给概率。

**这个集合是局面的属性，与谁来计算无关。** 任何正确的求解器，在同一个局面下算出来的"确定集"必然相同——不存在"我的确定层和你的不一样"这回事，只存在"你算得全不全"。

所以这一层没有"设计"的空间，只有一个工程问题：**怎样把这个已经定义好的集合高效、且不漏不错地算出来。**

### 2.2 怎么算：这是标准的模型计数问题

把每个已开数字格写成一条方程：

```
Σ x_c = 数字 − 周围已标雷数        （x_c ∈ {0,1}，c 取该格的未知邻格）
```

再加上一条全局约束：所有未知格里恰好还有 `M` 颗雷（`M` = 总雷数 − 已标雷数）。

剩下的就是"数模型"（model counting）问题：

1. **拆分量**：按"共享未知格"把边沿格连通成若干独立组件（并查集即可）。组件之间只通过总雷数耦合；
2. **组件内计数**：每个组件算出 `ways[k]` = 该组件恰好有 k 颗雷的自洽方案数（DFS + 约束剪枝，或 SAT/#SAT 求解器）；
3. **按总雷数卷积**：把各组件按雷数做卷积，再用空白格的组合数 `C(自由格, 剩余雷)` 补齐；
4. **取边际**：某格是雷的方案数 ÷ 总方案数。等于 0 或 1 的，就是确定集。

这是**标准的 #CSP / #SAT 计数**，教科书里有；工程上等价于"把局面翻译成一个很小的整数规划，然后精确数解"。不需要任何启发式，也不依赖直觉。

而且它天然吃掉两类"看起来需要聪明"的推理：

- **跨组件 + 总雷数的耦合**：两个组件各自"1 颗或 2 颗"，而全盘只剩 3 颗 → 两边都被钉死。单看任何一个组件都推不出来，卷积一下就有了；
- **多约束联立**（1-2-1 这类）：单独看每条约束都推不出，按方案数一数就出来了。

### 2.3 唯一的边界：算得动算不动

组件枚举的规模通常很小（中盘一个组件 5–30 格）。真正的手段是**预算 + 退化**：组件太大时（实测 41–73 格、几十万到几百万节点的量级）就放弃精确解，退回局部窗口，而不是硬算。

退化只影响"**漏掉一些本来能确定的格子**"，不会把不确定的算成确定的——前提是求法本身是 sound 的（推出来的都对）。

### 2.4 两种错误的代价完全不同

- **把不确定当成确定**（假确定性）：求解器会毫不犹豫地点下去，直接送命。这类 bug 不会报错，只表现为"胜率莫名低几个点"。
- **漏掉确定的格子**：只是白赌一次，亏一次猜测机会。

所以这一层唯一的正确性判据是：**表里每个 0/1，都必须在所有自洽雷图里成立**。我们做过核对：12 张高级盘、120 步、**129,419 条 0/1 结论，零矛盾**。

### 2.5 参考实现的差别只在"求法"

EdLogg 用 `RULE_1`/`RULE_2` 加"单组件内的强制赋值传播"去**求**这个集合；Hill 用组件枚举 + 总雷数卷积直接**取边际**。

**目标集合是同一个**，区别只在实现：传播快，但可能漏（尤其跨组件 × 总雷数这一类），漏了就等于多赌一次；计数慢，但在预算内不漏。两者都是求同一个确定集的工具，不是两套不同的"确定性层"。

## 三、第二层：概率——本文的基准

有了第一层，每个未知格的雷概率就是精确后验（在组件分解 + 总雷数约束下）。那么最自然的选择就是：**取概率最小的那一格，点开**。

**这条策略就是本文的基准（baseline）**：

> 确定性层做满（§2）→ 精确边际概率（本节）→ 并列时随便挑一个最小概率格点开。

它在 16×30/99 上的胜率是 **50.2%~50.5%**（几十万局）。而 Hill 的完整实现是 54.59%——也就是说：

**一个只有"精确计数 + 最安全格"的求解器，已经拿到了 Hill 大约 92% 的成绩；剩下那 4 个点，才是猜法层的全部空间。**

本文后面所有的"改进"，都是在这条基准上加东西、跑同盘 A/B，**不是**在 Hill 的 Java 代码上打补丁。

不过基准有一个明显的弱点：**概率相同的时候怎么办？** 实测高级盘里，**约 72% 的"必须猜"的局面存在多个并列最低概率的候选**。这就是猜法层真正的战场。

## 四、第三层：Hill 的猜法是怎么做的

### 4.1 为什么"最低概率"不是最优

直觉上，选存活率最高的格子是局部最优。但**胜率是连乘**：

```
这一手活下来 × 之后还能活多久
```

两个候选：

- A：安全率 0.70，但点开只得到一个数字；
- B：安全率 0.72，点开后能连锁解开一大片。

A 的"这一步"更好，B 的"之后"更好。哪种对全局更有利，取决于"解开一片"值多少——这不能用局部概率回答。

### 4.2 Hill 的完整猜法层

Hill 的求解器分五层：

| 层 | 做什么 |
|---|---|
| 1 | 平凡分析（单格的 1-2-1 之类） |
| 2 | 概率引擎（组件枚举 + 总雷数，出每格雷概率） |
| 3 | 50/50 检测（两格共享一颗雷、永远不会被分开） |
| 4 | **猜法逻辑**（本节重点） |
| 5 | 深搜（候选方案少时，直接在所有雷图上做期望最大） |

第 4 层的完整流程：

1. **选候选**：令最安全格的概率为 `p_min`，把所有权概率不超过 `p_min + 0.1` 的未开格放进候选集（**10 个百分点的带宽**）；
2. **算 progress**：对每个候选，假设它安全，估算"下一手能不能出现 100% 安全的动作"——能，就算高"推进价值"；
3. **算 secondary safety**：这一手安全 **且** 下一手仍安全的联合概率；
4. **合成**：`score = P(安全) × E[下一手最高存活率]`，取最大者；同分按 progress 排。

一句话概括：**它不是"选最安全"，而是"在差不多安全的格子里，选那个能把局面带向确定的"**。带宽的作用是给"信息"留出用风险换的空间——最多允许牺牲 10 个百分点的安全率。

第 5 层（深搜）在候选方案数少于 4,000 时接管：直接在所有自洽雷图上做期望最大搜索，逐格算真实胜率。

**这两层的价值差距极大**：关掉第 5 层只掉 0.37 点，关掉第 3 层（50/50 检测）掉 0.13 点，而**关掉第 4 层的候选重排要掉 1.75 点**。

### 4.3 另一种口味：EdLogg 用规则序列

EdLogg 的猜法不是打分，而是一串规则（`MakeMove` 里的状态机）：

1. `GUESS_0`：取最低概率格，再叠加一个"横竖一致性"的几何检查；
2. `SUPERLOC`：**故意离开边沿**，去点内部空白格。他用 `exposed = 1 − 非边沿概率 + 面积 × 安全率` 估算"这一下能炸开多大一片"，只要炸得够大，就愿意承担更高的雷概率；
3. `GAMETREE`：方案数 < 1000 时，对方案做期望最大深搜；
4. `GUESS_1` / `GUESS_2`：概率表不可用时的兜底。

风格完全相反：Hill 用连续打分、在"最安全格附近"挑；EdLogg 用离散规则、会主动跑到远处赌一把。结果就是开头那组数字——**EdLogg 每局少猜 0.37 次，胜率低 0.6 点：他用更少的赌，换更重的赌。**

## 五、在基准上做改动：14 种猜法的实测

下面每一项都是"**§3 的基准 + 单一改动**"，同盘 A/B，高级 16×30/99。基准本身是 50.2%~50.5%。

### 5.1 先把 Hill 的猜法"照抄"一遍：−0.65 点

我们按 4.2 的四步实现了一版：候选带宽 10%、progress、secondary safety（用采样估下一手）、合成分。

结果 **49.80% vs 基准 50.45%**，即 **−0.65 点**，而且慢 12.8 倍。

查下来问题在"secondary safety 靠采样估"：32 张样本 × 400 个未知格，会冒出十几个"0/32 次是雷"的格子，被误判成"必然安全"。改成"按观测分组、每组重建假设棋盘再精确重算"之后，只回到 49.0%——**仍然不过基线**。

**结论：Hill 的打分函数在他自己的实现里有效（关掉掉 1.75 点），但单独搬到另一条基线上并不自动有效。** 他的 progress / secondary 都是近似量，而且和他的概率引擎、深搜阈值耦合在一起。

### 5.2 把"下一手"从采样换成精确重算：+0.67 点

顺着 5.1 的诊断，只改一件事：**不再用采样估"下一手的最安全存活率"，而是按观测把局面分叉，对每个分支重新做一次精确计数**。

结果：**51.19% vs 50.52%，+0.67 点（z=2.42，10,000 局）**——这是所有单项改动里最好的一次。

它说明 Hill 那层真正的价值不在"打分公式"，而在"**用下一手的信息量给候选排序**"；公式里的采样近似才是瓶颈。

### 5.3 把"信息"算成"还剩几次赌"：+0.30 点（噪声内）

另一个思路：信息量 = "点开这一格之后，还有多少个边沿组件没有被总雷数钉死"。

- 估计方式：假设开 `c` → 连锁展开到不动点 → 重建约束系统 → 数"还剩几个组件没被钉死"；空白区按"每次猜测平均扫开 40 格"折算；
- 打分 `score = (1 − p) × Q^(n_after − 1)`，`Q ≈ 0.775`（从实测反推的"每次猜测平均存活率"）。

结果 +0.30 点（2,000 局，z 不到 1）。原因很实在：**88% 的中盘局面里这个估计根本算不出来**（组件 40~70 格，精确枚举超预算），退化成基线；只有在残局里它才真正生效，而那部分已经被深搜覆盖了。

### 5.4 精确条件计数：+0.14 点

再进一步：对每个候选，精确算"它安全且翻出数字 k"的概率分布，再按概率加权评估后续价值：

```
V(c) = Σ_k P(c 安全且翻出 k) × Q(条件于 k 的续局价值)
```

结果：**+0.14 点（100,000 局，z=1.46）**。真实、但很小——小到需要十万局才能和 0 区分开。

### 5.5 全景表

| 猜法 | 相对基准 | 备注 |
|---|---|---|
| **精确重算的 progress**（5.2） | **+0.67** | z=2.42，当前最好的单项 |

### 5.6 三种失败模式

1. **代理指标失真**：用"解开面积 / progress / 二次存活率"这类东西替代"整局胜率"，在 72% 的并列局面里几乎必然选错（`blank −9.6` 最典型）；
2. **估计不稳**：用采样估概率，会在罕见格上冒出"0/32 次是雷"的假象，一个假安全直接吃掉整局；
3. **改善被噪声淹没**：+0.1~0.3 点的改动，需要 10 万局才能和 0 区分开——**这就是为什么这个领域的"改进"大多不可复现**。

## 六、对 Hill 的改进尝试：加法几乎都是零头

先说"减法"——把他的每一层单独关掉，看掉多少（他自己那份 10,000 局 A/B）：

| 关掉的东西 | 胜率变化 |
|---|---|
| 候选重排（第 4 层） | **−1.75 点** |
| 全盘深搜 | −0.37 点 |
| 50/50 检测 | −0.13 点 |
| 长期风险模块 | +0.07 点（关掉反而略高） |

**价值集中在第 4 层**：深搜和 50/50 检测都只是零头，长期风险模块在 1 万局的尺度上甚至是负的。

再说"加法"——各路改进尝试的实测：

| 尝试 | 结果 | 代价 |
|---|---|---|
| **按需加深**（深搜被跳过时，补一次"证据充分"的局部深搜） | **+0.08 点**（95% 区间 [−0.02, +0.19]） | 墙钟 +26% |
| 用 Python 复刻"按需加深" | −0.01 点（10 万局） | 慢 12 倍 |
| 精确重算的 progress（§5.2） | +0.67 点 | 慢 4~8 倍 |

### 6.1 "按需加深"具体做了什么

Hill 的深搜有个硬限制：只在候选方案数 < 4,000 时跑，中盘必然爆，于是退回"单格最低概率"。那次改进补的正是这个缺口：

1. 枚举至多 40,000 张**等权**一致雷图（用约束传播 DFS，比直积快几个数量级）；
2. 用同一个便宜的续局策略，给"原选点"和候选分别打分；
3. 某候选领先超过 **0.5 个百分点**（门槛写成 `200 × gain ≥ layouts`）才触发加深分析（≤130 万节点）；
4. **能证明更优才改点**。

成绩：54.75% → **54.83%**（+0.08 点），墙钟 +26%；10,000 局里触发 198 次、改点 120 次、涉及 114 张盘，其余 9,886 盘逐盘一致。

### 6.2 为什么加法这么难赚

1. **深搜只在"无论如何都要赌"的局面改变选点**。而这些局面里，各候选的真实胜率往往挤在 40%~60%，算得再准也只值零点几个点；
2. **门槛本身就说明了预期**：0.5 个百分点的门槛，等于承认"改动的平均收益小于 1 点"；
3. **成本是线性的、收益是亚线性的**：多算一次就多花一次时间，而胜率只涨零头。

**到 54% 附近，剩下的空间是十几个 0.1~1 点的小项，而不是一个 5 点的大招。**

## 七、两个参考实现为什么这么像（出处考证）

EdLogg 在 `ReadMe.txt` 里写过一句：

> "David Hill using the Reddit name BinaryChop has the most interesting solver and the best analyzer I have seen"

并在 TODO 里列了：

> "Speed up the create solutions using the web idea that BinaryChop using in the jar version."

所以"思想同源"是有据可查的：至少是**读了对方的实现、公开致敬、并采用了对方的解生成思路**。

但两者的主体结构是各自长出来的：

| | Hill | EdLogg |
|---|---|---|
| 确定性 | 平凡规则 + 概率引擎取 0/1 | `RULE_1`/`RULE_2` + 强制传播 |
| 概率 | 组件枚举 + 总雷数 | 周长 list + 组合加权 |
| 并列选择 | 打分函数（progress × secondary） | 规则序列（GUESS_0 → SUPERLOC → GAMETREE） |
| 残局 | 方案 < 4000 时深搜 | 未开格+余雷 ≤ 64 时暴力 |
| 风格 | 打分/分层 | 规则/状态机 |

**共同点是数学，分歧是工程口味。** 这也解释了为什么两者胜率只差 0.6 点：确定性层是同一个问题、同一个答案；猜法层各自近似，效果半斤八两。
