# 胜率是怎么构成的：从精确求解到"怎么猜更好"

本文把"高级 16×30/99、首点 (3,3) 九宫格安全"这个固定规则下的胜率拆成可分别度量、可分别优化的几层，
并给出每一层我们的实测数字、理论上限、以及"最后的优化版 Hill"在这张图上落在哪。

所有数字都注明来源：`ALGORITHM_LOG.md` = 本仓库的日志；`codex 评审` = 2026-11-18 那份对同 1 万张盘的独立复算
（见 `docs/benchmarks/hill-adaptive-ab/` 与本机 `run-summary.txt`）。

---

## 0. 一句话版

**胜率 = 确定性推理覆盖的部分 × 每次被迫冒险的存活率连乘 × 冒险之后局面还值多少。**

第一项已经吃干净（我们的精确边际包含全部确定性结论，且经暴力枚举验证）；第二项由盘面决定、无法改变；
**能动的只有第三项——"在几个同样安全的格子里挑哪个"，以及"把哪些风险留到什么时候"。**
这也正是 Hill 的求解器比我们高 2~3 个百分点的位置。

---

## 1. 三层结构

### 第 1 层：确定性展开（不承担任何风险）

规则：每个已开数字格 `n` 给出约束 `Σ x_邻格 = n − 已标雷数`，外加"剩余雷数"这一条全局约束。

- 当某格的雷概率被约束系统逼成 `1` → 直接标雷；逼成 `0` → 安全，可以直接点。
- 我们已经证明：**在真实可达局面里，我们的精确边际就是完整约束系统（含总雷数）的后验**，
  152 个可达局面 / 814 格与暴力枚举 0 处不一致（`docs/KNOWN_ISSUES.md` 的"方案二"）。
  因此第 1 层我们与 Hill 等价，甚至更完整（Hill 的 `ForceExpose/ForceMine` 只在单个周长列表内部推导，其集合是我们的子集）。
- 第 1 层能解决多少，是盘面决定的：**10,000 张盘里有 16.2% 一张都不用猜就能赢**（codex 评审复算）。
  也就是说 83.8% 的盘，胜率在第 1 层结束时就锁定在 1，剩下的盘开始打折。

### 第 2 层：被迫冒险（由盘面决定，不可优化）

- 第 1 层推不动时，必须点一个"有雷概率"的格子。当前局面里最安全的格子存活率
  `s* = 1 − min p_c`，这个 `s*` 只由盘面决定：任何策略都至少要承担它。
- 每次冒险存活率实测约 **0.77**（我们的猜测概率均值 0.193；Hill 的 `prob` 连乘 0.55 对 2.24 次猜测 ⇒ 0.766）。
- 猜测次数 `n` 由"能不能解开"决定，实测我们 2.6~2.7 次/局、Hill 2.24~2.4 次/局（口径差异见 §5）。
- 结论：**P(整局) ≈ q^n，q 已经到底**（我们本来就挑最安全格），所以"少猜"是第 1 层的事，
  不是猜法的事——PERF-7（少猜优先）、PERF-10..18 的一堆尝试都在证明这一点。

### 第 3 层：同风险的并列候选——真正的战场

这是本文的重点。

**现象**：在 8,380 个"双方都要猜"的相同局面里，**约 72% 存在多个雷概率并列最低的候选**（codex 评审）。
它们"这一步别死"的价值完全相同，但**点下去之后看到什么、后续还要冒几次险，完全不同**。

**证据（这是整份文档里最重要的一张表，同一批 10,000 张盘、同一首点）**：

| 策略 | 胜率 | 说明 |
| --- | ---: | --- |
| 我们默认（`min_prob`，并列时取行优先） | **51.84%** | 基线 |
| 只把"首次常规猜测"换成 Hill 的选点，其余照旧 | **52.92%** | **+1.08 点** |
| Hill Java（`LARGE_ANALYSIS`） | **54.35%** | |
| Hill 关掉全盘深搜 | 53.98% | −0.37 |
| Hill 关掉全盘深搜 **且关掉候选重排** | 52.23% | **再 −1.75** |

两个关键读数：

1. **只换首猜就 +1.08 点**，而且是在**同一步存活率从 82.0% 降到 76.4%** 的前提下拿到的：
   即"更危险的一步，换来了更好的后续"。在"两种首猜都安全"的 5,704 局里，Hill 的选点多赢 155 局，
   扣掉首猜多踩的雷，净多赢 108 局。
2. **Hill 自己的候选重排价值 +1.75 点**（52.23 → 53.98），而他的 50/50 检测和长程风险模块只有
   +0.07 / −0.13。也就是说他比我们强的地方**不在"算概率"，而在"并列时怎么挑"**。

### 为什么"挑哪个"能值 1 个点

设候选 `c` 的雷概率 `p_c` 相同，但"点开后看到的数字"这个观测 `O_c` 不同。整局胜率是

```
V(c) = (1 − p_c) · E[ V(局面 + O_c) | 安全 ]
```

`p_c` 相同 ⇒ 差别全在 `E[V(·)]`。观测 `O_c` 有三类价值：

- **解开新约束**：新数字可能把某些格子逼成 0/1（把下一次冒险直接消掉）。
- **降低下一次风险**：把下一次猜测从 5 个候选缩到 1 个，或从 0.5 变成 0.9。
- **证明"这里必须 50/50"**：早点知道是死局，可以尽早把代价付掉（这是 Hill 的 50/50 检测在做的事）。

反过来，如果两个候选"看到的东西一样"，那它们对 `E[V]` 的贡献严格相同——这时挑谁都一样。
**并列候选的价值差，等于它们"看到不同数字"的概率 × 不同数字带来的局面差。**

### 上限在哪

- **规则性上限**：有些盘的两种雷图只交换一对格子的雷位，其他格子给出的数字完全一样，任何策略都必须 50/50。
  因此 100% 不可能，Louf 2025 证明了随机大棋盘在雷密度足够大时最优胜率趋近于 0（`arXiv:2506.01634`）。
- **宽松上界**：对同一批 10,000 张盘，假设"活过第一次猜测之后一律算赢"，得到的上界是 **85.37%**
  （95% 抽样区间 85.06%–85.67%，codex 评审）。它只能用来排除"上限很高"这种猜想，没有指导价值。
- **可达上界**：目前没人给出这套规则下的精确最优值。已知的强基线是 54%~55%（Hill 54.35~54.83、
  EdLogg 52.50、我们 51.84~52.92）。**54.8% 不是数学上限，只是当前最好的工程实现**。

## 2. 把"猜得更好"翻译成可执行的算法

按信息价值排序，一共四种做法，成本与收益都是实测量过的。

### 2.1 精确的条件分支计数（推荐，唯一还没做对的一条）

现在的 `choose_open_progress`（PERF-16）是它的**采样近似**：最多保留 4 个观测分支、丢弃权重 <15% 的分支、
再用 32 次采样估"下一手能不能出现确定格"。它拿到 +0.19 点（51.84 → 52.03），远小于 Hill 的 +1.08。

正确做法是把它换成**精确条件计数**，而这些零件我们都已经有了：

1. 对候选 `c`，用 `frontier` 的组件枚举 + 总雷数卷积，算出
   `P(c 安全 且 翻出数字 k)` —— 对每个组件的配置按 `cell_ways` 拆分，再做一次卷积即可，不需要采样。
2. 对每个观测分支 `(k, 概率)`，重建假设棋盘，算"这一支里还剩几个必须猜的点、下一次冒多少险"。
3. `score(c) = Σ_k P(分支 k) · (下一手最高存活率)`，取最大者；平局再按"能否产生确定手"排。

代价：每个候选要跑一次分支重算。用增量约束（PERF-17 的 `IncrementalBuilder`）可以压到毫秒级；
10k 盘 × ~2.5 次猜测 × 5 候选 ≈ 12.5 万次分支评估，按当前 3 ms/次估约 6 分钟，完全可接受。

这条是 Hill 的 `SecondarySafetyEvaluator` 在做的同一件事（他按候选算"这一手 + 下一手都活下来的概率"），
区别只在于我们用精确计数代替采样——这正是他 +1.75 而我们只有 +0.19 的原因。

### 2.2 同分候选的"信息量"排序（便宜的先做）

如果不想算分支，只用超便宜的代理量排序，实测有效的有：

- 未知邻格数（`deep`，PERF-14）：+0.05 点，噪声级。
- "所在空区大小"（`superloc`，PERF-9）：−0.05 点。
- "翻出数字的种类数"（`living`，PERF-15）：−2.75 点。

**结论：这些代理都不行。** 信息价值必须真的算后续局面，不能用"能开多少格 / 能见多少种数字"近似。

### 2.3 按需加深（Hill 的最后一版：`LARGE_ADAPTIVE_ANALYSIS`）

只在"全盘深搜超预算、回退成单格猜测"时启动：枚举 ≤4 万张等权雷图 → 用便宜续局策略给原选点和候选估分 →
领先 ≥0.5 个百分点才做 ≤130 万节点的加深证明 → 能证明更优才改点。

- 收益 **+0.08 点**（54.75 → 54.83），代价 **+26% 墙钟**，置信区间跨 0。
- 我们复刻到 Python（PERF-18）后，10 万盘配对 −0.01 点（z=−1.18）：**不值得默认开启**。
- 它值钱的前提是"底座已经很好"——底座差 2 点时，这点收益被噪声淹掉。

### 2.4 整局规划（MCTS / rollout）

我们做过 `rollout`（PERF-6）、`gamble`（PERF-12）、`planner`（UCT，10 万盘 50.85 vs 50.24）。
全部 ≤ 基线 + 噪声，而且慢 2~6 倍。
原因：每次模拟都要跑一遍完整策略（建约束、精确边际、开格、判胜），而单次猜测的信息价值只有 0.1~0.5 点，
模拟噪声比信号大。

**这四种里，只有 2.1 还没被证伪。**

## 4. 结论：往哪改

1. **不要再碰"选什么格子才安全"**：精确边际已经是可达局面的完整后验，0/1 判定 1028 条零错判。
2. **不要再碰"少猜几次"**：`fewest`、`superloc`、`coin`、`living` 全部 ≤ 基线；猜测次数由盘面与第 1 层决定。
3. **唯一剩下的杠杆是"并列候选的信息价值"**，而它必须用**精确条件计数**来算（§2.1）。
   这是一个可以拆成三小步的工程活：
   - a) `frontier` 加 `conditional` 接口：给定候选格返回 `{观测: 概率}`（复用组件枚举 + 卷积）。
   - b) `guess.choose_open_informed`：按 §2.1 打分，替代 `choose_open_progress` 的采样。
   - c) 同盘 10k × 2 种子 A/B，与 `min_prob`、`progress`、Hill 首猜三条基线比。
4. 预期：如果 a)+b) 做对，应当接近 Hill 的 54.3%（他现在比我们高 2.5 点，其中 1.75 点已证明来自候选重排）。
5. 成本：单步多算 5 个候选的分支，约 +50~100 ms/局；可以接受（Hill 也慢 26%）。

## 5. 口径警告（读数字时必看）

- **发牌器**：不同发牌器同求解器差 ~0.8 点（我们盘的 51.22% vs EdLogg 盘的 50.45%，n=5000/2000，噪声内）。
  跨发牌器的数字不能直接相减。
- **猜测计数**：EdLogg 的 `guesses++` 也计"他能证明是雷的格子"，所以他的 2.24 次与我们 2.6 次不是同一把尺；
  用同一裁判（我们的精确表）复算，他真正无法确定的决策是 1.71 次/局。
- **样本量**：n=200 时 σ≈3 点，n=1000 时 σ≈1.1 点，n=10000 时 σ≈0.5 点。
  **任何 <1000 局的结论都不要当真**（本文所有关键结论都 ≥10k）。
- **胜局要严格判**：我们统计的都是"所有安全格都开出来"的严格胜，不用宽松的 `is_won`。
